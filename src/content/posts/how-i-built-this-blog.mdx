在这个信息过载、平台算法主导的时代，拥有一个完全属于自己的“数字自留地”显得尤为珍贵。

大家好，我是苏羽野。曾在亚马逊做卖家支持的我，每天面对着处理不完的 Case 和繁杂的规则。为了寻求突破，我开始向 Shopify 开发与运营方向转型。在学习新技术的过程中，我越发觉得需要一个干净、纯粹的地方来沉淀技术复盘、记录折腾经历，顺便展示一下我捣鼓的说唱音乐和对数码科技的碎碎念。

开源社区里鼎鼎大名的“安知鱼（Anzhiyu）”主题一直让我十分心动：精致的卡片化 UI、毛玻璃质感的导航栏、丝滑的暗黑模式，简直长在了我的审美点上。但如果直接使用传统的 Hexo 框架，后期想要接入一些个性化的动态功能（比如音乐播放器、API 接口调用）会受到不少限制。

于是，我决定迎接一个挑战：**用现代化的前端框架，借助强大的 AI 编程助手，从零写一个属于我自己的“安知鱼”。**

这篇文章，就是我这几天折腾的完整记录。

## 🛠 技术栈选型：现代前端的“三剑客”

为了保证极高的性能和未来二次开发的无限可能，我选择了目前前端界最主流的技术栈方案：

- **核心框架：Next.js (App Router)** 抛弃了纯静态的包袱，Next.js 既能实现极速的静态导出（Static Export），又能在未来随时切换到服务端渲染（SSR）。它的基于文件系统的路由管理极其直观。
- **样式引擎：Tailwind CSS** 用过就回不去的原子化 CSS。配合简单的 CSS 变量，轻松实现全站的亮/暗色主题无缝切换，再也不用维护几千行的 `.css` 文件了。
- **交互动效：Framer Motion** 博客里那些平滑的卡片悬浮（Hover）放大、标签云的浮动，以及页面切换时的淡入淡出，全靠这个动画库搞定。
- **内容解析：MDX** 不仅支持标准 Markdown 语法，还能在文章里直接插入 React 组件（比如交互式图表或播放器），极大地扩展了文章的表现力。

## 🤖 结对编程：当 AI 成为主程序员

虽然我对前端有所了解，但要从零手搓这么多组件，工作量极大。这次建站，我引入了“外挂”——**Claude Code** 终端助手。

我的工作流变成了：**我负责做架构师和产品经理（提需求），AI 负责做码农（敲代码）。**

> **💡 经验之谈：如何给 AI 下指令**
> 不要对 AI 说“帮我做一个安知鱼博客”，它会懵的。必须先定全局规范（比如规定必须使用卡片化设计、`rounded-2xl` 圆角），再按模块拆解需求，最后让它注入真实的 `userConfig.ts` 配置文件。

中间还发生了一个小插曲。因为我使用的是第三方中转的 API 接口，遇到报错提示：`The supported API model names are deepseek-v4-pro...`。通过排查，我发现在 `.claude/settings.local.json` 中配置的旧模型名失效了。利用命令行 `cc switch` 将底层模型无缝切换到 `deepseek-v4-pro` 后，AI 的代码生成能力瞬间满血复活，甚至比之前更聪明了。

## 🏗 博客基建：图床与互动

一个好用的博客，必须解决图片存储和评论互动两个痛点。

### 打造专属丝滑图床

Markdown 本地图片管理极易造成项目臃肿。我没有选择免费但可能随时跑路的公共图床，而是搭建了 **GitHub 仓库 + PicGo + jsDelivr CDN** 的极客方案。

现在，我只需要使用快捷键 `Ctrl + Shift + P` 截取屏幕，PicGo 就会自动将图片推送到我的专属 `blog-images` 仓库，并将经过 jsDelivr 全球节点加速的 URL 直接复制到剪贴板。国内访问秒开，且数据完全掌握在自己手里。

### 极简的 Giscus 评论区

评论系统我选择了完全开源免费的 Giscus。它依托于我博客源码仓库的 GitHub Discussions 功能，没有任何广告，不需要数据库，完美契合静态博客的理念。更赞的是，它的 UI 风格极简，并且能完美适配我网站的暗黑模式。
